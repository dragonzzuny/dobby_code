# Evidence and numbers

Applies to: every claim about the system, every number in any reply or report.

1. A number may appear only if a command/test/script produced it THIS session.
   Docs, READMEs, comments, and your own memory are snapshots — orientation
   only; re-measure before acting on them.
2. Name exact files/paths/lines for every anomaly. "3 failures" without the
   three names is not a finding.
3. Two counting/measuring methods that disagree: both are suspect. Reconcile
   before proceeding — the disagreement itself is usually the bug.
4. Load-bearing numbers come from repeatable commands (recorded in the ledger
   or a report); one-liners are allowed only for orientation.
5. Config values, declared paths, versions, and schema claims are hypotheses:
   verify each against the running system/disk before wiring (P-CONFIG-VS-REALITY).
6. Unverifiable-here claims (external services, other machines, environments
   this machine cannot reach) are stated as NOT VERIFIED, never assumed.
